# 专业读者证据合同

## 定位

专业读者产物属于**读者反应证据层**。它回答“作品实际给读者造成了什么体验”，不回答“作者该怎样修改”。

工作流中的信息分层固定为：

1. 用户聊天原文：不可变反馈证据。
2. 专业读者报告：只读阅读反应证据。
3. 编辑/结构/人物审阅：解释问题原因并提出候选修订方向。
4. 助手归纳的修订方案：等待用户确认。
5. 用户确认后的修订方案：成为任务决策记忆，投影到设定、大纲、Brief 与修订队列。

专业读者报告不得直接写入长期记忆、正文、设定或大纲。未被用户确认的阅读判断只能保存在当前审阅任务的 artifacts/result packet 中。只有用户确认后的修订方案可以成为 memory 中的规划约束。

## 画像选择

从项目的目标平台、题材标签、文风定位、叙事人称、作品长度和阅读场景生成一个主画像。画像来源优先级固定为：用户本轮确认 > 项目设定/投稿配置 > 当前扫榜或拆文产物 > 通用画像。必须记录 `profile_basis`；不得用目录名、书名或模型常识猜平台。默认只运行一个 `professional-reader` Agent；全篇验收、高风险回炉或平台迁移时，可在同一次 Agent 输出中增加一个对照视角，不额外启动多个读者 Agent。

主画像模式：

- `free_feed_mobile`
- `paid_serial_core`
- `relationship_community`
- `story_answer`
- `general_fiction`

文风镜头可多选：`fast_punchy`、`restrained_realism`、`relationship_tension`、`suspense_gap`、`immersive_world`、`light_humor`、`lyrical_atmosphere`。文风镜头只改变观察重点，不允许把作品强行改写成平台模板。

## 篇幅与成本边界

- 短篇：上下文预算允许时一次盲读全文，逐节记录反应。
- 短篇逐节生产：普通小节不额外调用专业读者；只在第 1 节、明确的重大反转/高潮、结尾或作者点名回炉的小节调用一次。里程碑报告默认是采用前的建议证据；若发现标题承诺断裂、因果不成立、人物身份连续性断裂或终局未回答标题，则升级为阻断并返回当前节或规划层。
- 长篇当前章/当前节：默认不调用；只有留存、人物可信度或承诺兑现出现风险时才增加读者镜头。
- 长篇里程碑/整卷/全书：按 Evidence Plan 的自然阅读单元读取完整正文，每个单元独立保存读者反应和末尾追读问题；最终只聚合各单元回执与关键证据，不把全书正文再次装入一个 Agent 上下文。
- 专业读者不重复执行机器门、人物合同或一致性扫描；已有证据只供编辑阶段合并，盲读阶段不得提前读取。

画像用于调整观察顺序，不是硬编码评分。平台不明时必须使用通用画像，不能猜平台。

## 与审阅的边界

- 专业读者：记录掉线、困惑、情绪、人物印象、期待与兑现。
- `story-explorer`：只负责按明确查询检索正文、设定和追踪证据；不得下结构结论，不得替代 `story-architect` 覆盖剧情或钩子维度。
- 身份连续性：记录主角的职业、能力、缺陷或生活习惯是否持续参与后文，还是开篇用完即弃。
- 配角真实感：记录重要配角是否拥有自身欲望、独立选择及其关系后果，还是只负责递文件、背锅或解释设定。
- 揭示余震：记录关键真相出现后，后续行动、关系和代价是否真的改变；只有惊讶、没有后果，视为余震不足。
- `story-architect`：解释剧情结构、压力和钩子为何失效。
- `character-designer`：解释人物动机、关系和弧线为何失真。
- `consistency-checker`：核对事实、时间线、能力和认知边界。
- `story-review`：合并证据、去重、分级，并生成候选修订方案。

读者报告与编辑判断冲突时，两者都保留。编辑不得用大纲替正文辩护；读者也不得把个人口味伪装成事实冲突。
