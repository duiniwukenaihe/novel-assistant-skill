# 长篇人物合同

人物表存在，不代表人物已经可写。长篇在 `character_design` 或 `story_bible` 被接受前，必须证明人物能够持续驱动多卷剧情；否则总纲、卷纲和章节 Brief 会放大早期缺口。

## 必过合同

### 主角发动机

- 稳定身份与叙事位置。
- 外部目标与内在需求/恐惧。
- 缺陷、误信或自我欺骗。
- 能力边界、代价与不能突然获得的专业能力。
- 起点、卷级变化里程碑和终局主动选择。

### 主要压力角色

- 独立目标与自洽理由。
- 可实际调用的权力、资源、关系或能力。
- 行动边界、失败代价和逐阶段升级路径。

### 关键配角与关系

- 关键配角有自己的欲望与边界，不只递证据、解释设定或救场。
- 关系必须写清利益冲突、责任债、互相需要及预期变化终点。
- 重要人物的出场阶段与成长责任要能落到总纲/卷纲，而不是只存一份静态小传。

## 文件兼容

合同按语义读取，不强迫单一目录格式。以下形式可以并存：

- `设定/人物.md`、`设定/角色档案.md` 或故事圣经中的合并人物表。
- `设定/角色/{角色名}.md` 的一人一档。
- `设定/关系.md` 中的关系债、出场和成长里程碑。

旧项目缺少合同时，保留现有正文并提示补建；只读审阅可以先输出风险。新增总纲、卷纲、细纲或正文前必须补齐。合同通过后投影为 `追踪/memory/active-cast.json`，章节上下文只召回当前人物及其别名，避免每章重复读取完整人物库。

## 正常写作链路

1. 故事圣经锁定全局人物发动机、关系网和跨卷变化。
2. 总纲、卷纲分配人物在各阶段承担的目标、压力和变化责任。
3. 细纲与 Chapter Contract 明确本章实际出场人物、当前目标、阻力、关系变化和章末状态。
4. 当前章 Context Pack 只召回细纲、契约、上一章交接或上一章正文提到的人物；未出场人物留在全局人物库，不进入本章 prompt。
5. 章节采用后只回写发生变化的人物状态、认知边界和关系债；下一章再按实际承接重新筛选。
6. 卷末或阶段审阅才重新检查完整人物弧线，防止长期漂移和配角工具化。
